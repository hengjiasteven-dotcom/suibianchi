# 随便吃

> 记录每一餐，吃得明白一点。

一个 Android 端的个人饮食记录 App：拍照或截图上传一餐，AI 识别出**餐名与食材**，确认后入库；按日 / 周 / 月回看吃了什么；结合自己的忌口与爱好，用对话的方式给出下厨或外卖的建议；还会周期性统计饮食结构，提醒哪些种类吃少了。

---

## 它解决什么问题

- 想记饮食，但懒得手打一堆食材 → **拍照就行**，AI 认完你再核对
- 记完就忘了，看不出自己吃得好不好 → **日 / 周 / 月三种视图 + 周期报告**
- 忌口和偏好记不住 → 对话里实时抽取，确认后长期生效，推荐时**硬约束排除**
- 想找人一起吃 / 看看别人吃什么 → **广场**：朋友圈、加好友、只发食物不闲聊

---

## 主要功能

### 记录

- 拍照 / 相册多选（最多 6 张），或者**纯文字**也能记
- AI 识别只出**名称**（餐名 + 食材），热量在你确认之后才由后台估算，不用干等
- 识别结果**必须先确认才入库**，可以改名字、删项、加项
- 照片存对象存储，私有空间 + 签名地址读取

### 日志

- 周 / 月 / 日三种视图，双指缩放切换
- 一天固定四餐（早 / 午 / 晚 / 夜宵），**每餐只有一条**，要改就改那一条
- 可以补录前两天

### 报告

- 近 7 天食材类别占比、最常吃的食材、缺口提醒
- 忌口和爱好的程度可以**直接在报告里改**，改完立刻影响后续推荐

### 推荐

- 一个真实的对话窗口，不是选单
- 边聊边理解：说到"牛肉太好吃了"会弹出「爱好」让你确认，说到"辣椒好难吃"会弹出「忌口」，还分三档程度
- 对话内容在退出或闲置 10 分钟后自动清空（会提前提示）

### 广场

- **朋友圈**：所有人发的餐食分享都在这里，卡片上先显示餐名、再显示食材，带图就显示图
- **加好友**：每人有一个 6 位 ID（小写字母 + 数字），按 ID 申请，**对方同意**才成为好友；对方会在广场看到一条申请提醒，可以接受或拒绝
- **好友分享**：只能发食物内容（今天吃的 / 一周占比），**不能发文字**
- 自己的 ID 可以改，但**只能改一次**，改完锁死

## 技术栈

| 层 | 选型 |
|---|---|
| Android | Kotlin + Jetpack Compose，最低 Android 7.0（API 24） |
| 后端 | Python 3.12 + FastAPI |
| 数据库 | SQLite（单文件，方便备份） |
| 图片存储 | 七牛云对象存储（私有空间 + 签名 URL） |
| AI | DeepSeek（图片识别 / 热量估算 / 推荐对话） |
| 反向代理 | Cloudflare Tunnel |

## 本地跑起来

### 后端

```bash
cd server
python -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env        # 按注释填密钥
.venv/bin/uvicorn app.main:app --reload --port 8000
```

接口文档：<http://127.0.0.1:8000/docs>

### 客户端

```bash
cd android
./gradlew assembleDebug -PapiBaseUrl=http://10.0.2.2:8000/   # 模拟器连宿主机
```

正式包：

```bash
./gradlew assembleRelease -PapiBaseUrl=https://你的域名/
```

签名信息放在 `android/keystore.properties`（**不入库**）。

## 自测

```bash
cd server
python tests/test_flow.py        # 主链路：登录 → 记录 → 识别 → 报告 → 推荐
python tests/test_social.py      # 广场：6 位 ID、加好友、朋友圈、私聊分享
python tests/test_site_auth.py   # 账号打通：短信与密码全部委托给站点
```

三个脚本都是独立可跑的，成功会打印「全部通过」。

## 隐私

- 手机号只用于登录、找回密码和识别设备
- 饮食记录、照片、忌口爱好存在自己的服务器上，**不用于广告**
- 照片走私有对象存储，读取时现签地址
- 位置信息只在你主动点"附近店铺"时读一次
- 注销账号会删除全部记录、档案与设备信息

详见应用内「隐私政策」页。
